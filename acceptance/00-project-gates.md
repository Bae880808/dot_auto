# Project acceptance gates

Research-first delivery. Implementation may begin only after the preceding evidence gates pass. Each stage requires its own acceptance record; incomplete observations are not a pass.

## Stage gates

1. 100 long-tail keyword rows, each with keyword, tool/comparison/learning/purchase intent, top-three tool-page classification, existing tool availability, one-sentence differentiation opportunity. At least 60 tool-intent queries, not 60 separate tools. Record search source, locale limitations, time and URLs. Unknown observations cannot be passed off as inspected.
2. 10 selected queries, each top five observed organic results opened in browser and screenshotted. At least 50 screenshots, file names include safe URL representation and date, manifest preserves full URL/query/rank/time. One evidence-based common weakness summary per query. Do not force a negative finding when unsupported.
3. One tool template plus home. Nine modules: input, results, formulas, instructions, numeric examples, assumptions/limits, related internal links, FAQ, sources/update date. Real mobile Lighthouse Performance/SEO/Accessibility each at least 90; mobile screenshots. A subjective 'better than all competitors' claim requires transparent criteria, not a self-awarded fact.
4. Eight distinct functional tools, each EN and ZH (16 localized tool URLs). Script checks unique titles, H1, four FAQs, at least three internal links, schema, no broken links. All green.
5. Fix and rerun audits; two consecutive all-green rounds. Zero broken links, duplicate titles, missing schema and mobile horizontal overflow.
6. Per localized tool page two numeric worked examples, formula conventions, four real People Also Ask questions with provenance. At least 600 unique English words or 600 Chinese characters, excluding repeated boilerplate; these are different units and must be labeled. Missing PAA remains missing, not invented.

## After stage six

One queue item at a time, P0 blockers before P1 ranking before P2 expansion before P3 assets before P4 maintenance. For each: test, append log, check real time, next item. P0 > 0 blocks P2. Every three new tools requires P1 full-site review. Maximum 20 functional tools total. Read the current changelog before work; no repeated completed tasks. Do not change niche/framework or add large dependencies. Every improvement needs screenshot/script/link evidence. No extra pages merely to fill time.

Log: CHANGELOG/YYYY-MM-DD.md, each line time | ID | action | evidence | pass/fail | next.

Final HANDOFF.md: site access/page count/test status; remaining queue/priorities; three real decisions with options/recommendation (do not invent decisions merely to fill slots); skipped work/risks. Deliver verified preview URL, test output and top three keyword investment hypotheses.

## Integrity and costs

No invented ranks, screenshot evidence, PAA text, traffic volume, revenue, scientific benchmarks or Lighthouse scores. Offered competitor prices prove offers, not sales. EN/ZH availability alone is not a competitive moat. This research snapshot contains no payment integration, paid API, account signup, credentials or ad enrollment. No private personal data should be published.
